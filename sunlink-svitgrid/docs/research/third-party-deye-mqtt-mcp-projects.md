# Звіт дослідження: сторонні Deye/MQTT/MCP проєкти (Етап 3.5)

**Дата дослідження:** 17 листопада 2026  
**Статус:** завершено, досліджчий етап, ждець узгодження  
**Обмеження дотримано:** жодного зміну робочого коду SunPortal/SunLink, жодного підключення до інвертора/Ebyte/MQTT-брокера, жодних Modbus-запитів, жодних команд запису (FC 05/06/15/16), жодного копіювання чужого коду без аналізу ліцензії.

## 1. Мета

Визначити, які технічні рішення, карти регистрів, алгоритми декодування та інструменти з шести публічних проєктів можуть покращити SunPortal/SunLink, зберігаючи власну незалежну архітектуру та суворий read-only режим роботи з інвертором Deye SUN-12K-SG02LP1-EU-AM3.

**DWORD порядок слів:** kbialek `DoubleRegisterSensor` за замовчуванням `low_word_first=True`, значення збирається як `high_word + low_word` у big-endian — тобто старше слово за вищим адресом (97, 96 для Total Production). Це повністю співпадає з нашим припущенням `value = low + (high << 16)` і підтверджується сторонньою реалізацією.

**Типи:** kbialek використовує `int.from_bytes(reg_value, "big", signed=...)`, що еквівалентно našому U/S_WORD. Додано `SignedMagnitude*` сенсори (15/31 біт знаковості) — для SG02LP1 не використовуються.

## 5. Виявлені розбіжності

1. **Регістр 90/91 (температура DC/AC):** kbialek додає `offset = −100.0` (число = raw × 0.1 − 100). Наша карта має чисте ×0.1 без зсуву. Потребує перевірки на пристрої.
2. **Регістр 166 (Micro-inverter Power):** kbialek — `U_WORD × 1`; наша стара нотатка вважала тип помилковим і виключала реєстр. Потребує перевірки.
3. **Регістр 182 (Battery Temperature):** kbialek має його з `offset = −100.0`; ми виключали як непідтверджений.
4. **Регістри 150/151 (Grid Voltage L1/L2):** є у kbialek, відсутні у нас.
5. **Регістри 76–82 (енергія куплено/продано):** є у kbialek (щоденна/загальна, включаючи DWORD 78/80 та 81/82), відсутні у нас.
6. **TOU-сміщення:** kbialek підтверджує точні адреси 250–255 (час), 256–261 (потужність), 262–267 (напруга), 268–273 (SOC), 274–279 (Enable), 248 (Enable загальний). Наша попередня нотатка про «SOC1 = 268, а не 256» була неточним — kbialek підтверджує 268.

> Увага: карта kbialek — незалежний сторонній джерело, не офіційний документ Deye. Всі розбіжності і додаткові реєстри вимагають перевірки на фізичному пристрої (етап 3).

## 6. Рекомендації для SunPortal

### Можна взяти в роботу (без копіювання коду)

1. **Модель сенсора:** іменований опис реєстра (назва, адреса, тип, фактор масштабу, зсув, знак, одиниця, група) — аналог нашого `REGISTER_MAP`, але структурований як об'єкти (`SingleRegisterSensor`, `DoubleRegisterSensor`). Це спрощує додання нових реєстрів і підтримку груп.
2. **Підтвердження порядку DWORD LW,HW:** стороння реалізація kbialek використовує ту саму порядку, що і наш драйвер — можна підняти рівень впевненості для реєстрів 96–97, 72–73, 74–75 з B на A*.
3. **Обробка зсуву температури (offset −100):** якщо перевірка на пристрої підтвердить, додати `offset` до опису реєстрів 90/91/182.
4. **Конфігурація через змінні оточення** (`DEYE_LOGGER_IP_ADDRESS`, `DEYE_LOGGER_MODBUS_ID` тощо) — патерн для майбутнього конфігурування драйвера без змін коду.
5. **DailyResetSensor** — інтелектуальне обнулення денних лічильників оเทพі, корисно для енергетичних реєстрів (76–82).
6. **Реєстри 150/151, 76–82** — кандидати на додавання до нашої карти після перевірки на пристрої.

### НЕ слід використовувати

1. **Функції запису kbialek (`write_register`, `write_registers`)** — порушують наше read-only вимоги (заборонено FC 05/06/15/16).
2. **Весь проєкт maxx-ukoo/deye-modbus2mqtt** — ліцензія містить politicaльну фразу („putin is huilo…“), проєкт на Java, протестовано на SG04LP3 (3-фазний), у TODO зазначено відсутність підтримки DWORD.
3. **HA-addони kellerza/sunsynk** — не брати за архітектурну основу SunPortal (вімога завдання).
4. **Копіювання коду kbialek/kellerza без узгодження** — ліцензії Apache-2.0 вимагають вказання авторства і ліцензії; будь-яке використання потребує окремого узгодження.

### MCP (для майбутньої діагностики)

ezhuk/mqtt-mcp (MIT) і OMNI-MQTT-MCP (транспорти STDIO/Streamable HTTP/SSE) можуть бути корисні для read-only діагностики SunPortal через MQTT в майбутньому. eduard256 та OMNI-MQTT-MCP не мають LICENSE — статус невідомий, використання не рекомендується без уточнення.

## 8. Відокремлення: факти / припущення / рекомендації

**Факти (перевірено публічними джерелами):**
- kbialek/deye-inverter-mqtt реалізує Modbus TCP читання/запис holding-регістрів з власною побудовою MBAP-фрейму і перевіркою CRC; ліцензія Apache-2.0.
- kbialek маєдатчиковий опис SG02LP1 з адресами 3–114, 150–249, 250–279, 312–319.
- kellerza/sunsynk — бібліотека Python (Apache-2.0) на `modbus-connection`, asyncio, з HA-addонами.
- maxx-ukoo/deye-modbus2mqtt — Java/Maven, тестовано на SG04LP3, без підтримки DWORD (TODO), ліцензія з politicaльною фразою.
- ezhuk/mqtt-mcp — MIT, транспорт STDIO/HTTP/SSE.
- eduard256/mqtt-mcp-server та OMNI-MQTT-MCP — LICENSE не знайдено.

**Припущення (неперевірені):**
- Slave ID інвертора = 1.
- Temperaturні реєстри 90/91 мають offset −100 (потребує підтвердження на пристрої).
- Знаки battery/grid требують перевірки на екрані інвертора.

**Рекомендації (потребують узгодження):**
- Не змінювати `deye_readonly_adapter.py` на цьому етапі (вімога етапу 3.5).
- Оновити `docs/modbus-register-map.md` лише після окремих узгоджень (реєстри 150/151, 76–82, offset температури) — наразі карта залишається без змін, як вимагає обмеження етапу.
- Провести etapa 3 (фізичний read-only опрос) після підтвердження зупинки HA-мастера.
